# 거래 멱등성 비용의 리그 자동 동기화 제외 실험

`league.auto-sync.enabled`의 기본값은 `true`다. `false`이면 원본 거래 커밋 후
자동 동기화와 예약 재시도가 DB에 접근하기 전에 반환한다. 리그 조회에 필요한
명시적 `reconcile` 호출은 유지한다. 거래 원장, 멱등성 기록, 회원·포트폴리오
잠금, 스키마와 HTTP 계약은 변경하지 않는다.

개발 서버에서만 실험 중 `LEAGUE_AUTO_SYNC_ENABLED=false`를 적용하고 재기동한다.
운영 설정에는 적용하지 않는다. 기존 설정은 값 노출 없이 백업하고, 종료 후
원래 값으로 복구한 뒤 정상 응답과 자동 동기화 재개를 확인한다.

측정 전에 신규 실험 회원의 거래를 등록하고 다음을 확인한다.

- 실행 중 JVM의 해당 설정이 `false`다. 다른 환경 값은 출력하지 않는다.
- 거래·보유수량·멱등성 기록은 예상대로 저장된다.
- 해당 회원의 `shared_portfolios`와 관련 리그 보유·이력은 생성되지 않는다.
- 공유 포트폴리오가 이미 있는 별도 실험 회원은 거래 후에도 공유 이력이 변하지 않는다.

같은 JAR·JVM·DB 풀 설정에서 키 없는 신규 등록과 매 의도마다 새 키를 부여한
등록을 비교한다. 완료된 키 재시도는 신규 등록과 분리한다. 조건마다 초기 이력,
회원 수, 요청 내용을 맞추고 순서를 번갈아 반복한다. SQL 수와 물리 연결 생성,
풀 차용 횟수는 서로 다른 지표다. 집계값을 요청별 SQL 수로 바꾸어 해석하지 않는다.

단계별 목표 RPS·실제 전송 수·발생기 미전송 수·HTTP 상태·클라이언트 타임아웃,
측정 시간과 제외 시간, p50/p95/p99·성공 완료 처리량·GC·풀 대기·DB 잠금 대기를
남긴다. 완료를 알 수 없는 요청은 같은 키의 재시도 및 DB 대조로 확인한다.
발생기와 앱이 같은 서버를 사용하면 운영 최대 처리량이라고 주장하지 않는다.
실험 계정만 소유 확인 후 백업·정리하고 잔여 행 0건과 서비스 정상 상태를 검증한다.
