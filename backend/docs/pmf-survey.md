# PMF 설문 API 운영과 집계

관련 작업은 FE #805와 BE #809입니다. Flyway V86이 방문 이력, 응답, 숨김 기한을 저장하는 테이블을 만듭니다.

실행 환경에서 `PMF_SURVEY_ACTIVE_ID`에 캠페인의 양의 정수 ID를 지정하면 설문을 시작합니다. 기본값 `0`에서는 현재 설문 조회가 204를 반환합니다. 같은 ID를 다시 지정하면 기응답과 숨김 이력을 이어서 사용하고, 새 ID를 지정하면 별개 캠페인으로 집계합니다. 여러 서버를 운영하면 모든 인스턴스에 동일한 ID를 적용합니다.

| 메서드와 경로 | 동작 |
| --- | --- |
| `GET /api/pmf-surveys/current` | 활성 캠페인, 참여 가능 여부, 첫 방문 여부, 기존 응답 ID, 유효한 숨김 기한 조회 |
| `POST /api/pmf-surveys/{surveyId}/responses` | 선택지와 선택 이유 저장. 첫 저장은 201, 중복 제출은 기존 ID와 200 반환 |
| `POST /api/pmf-surveys/{surveyId}/snooze` | 다음 한국 시간 00:00까지 숨김. 성공 시 204 |
| `GET /api/admin/pmf-surveys/{surveyId}/results` | 관리자 전용. 캠페인 전체 응답 수, 그룹별 응답 수와 선택지별 인원, 최초·최종 응답 시각, 모집 경로(`IN_APP`) 조회 |

응답과 숨김에는 기존 `GET /api/auth/csrf`가 발급한 쿠키와 헤더가 필요합니다. 회원은 계정으로, 비회원은 기존 서명된 `content_visitor` 쿠키로 구분합니다. 관리자 계정과 `staff.daynomy.com` 접근은 참여에서 제외합니다. 팀원 도메인의 요청은 프록시에서 원래 Host를 유지해야 합니다.

설문 상태 조회와 수동 분석 요청에서 처음 관측한 HTTP 세션을 기록합니다. 세션이 같으면 첫 방문 상태를 유지합니다. 이전 세션을 관측한 회원·비회원은 재방문으로 판정하며, 도입 전 방문 기록이 없는 사용자는 첫 방문으로 처리합니다. 비회원의 쿠키를 삭제하거나 기기를 바꾸면 새 응답자로 인식할 수 있습니다.

공식 집계는 분석 버튼으로 시작된 수동 분석·재시도 요청이 서버에 도착한 시각을 사용합니다. 이후 분석이 실패해도 기록을 유지합니다. 자동 분석과 결과 조회는 제외합니다. 활성 캠페인 설정과 별개로 분석 요청을 관측하므로 설문을 열기 전에도 이력이 쌓입니다. 기존 PostHog 이력은 가져오지 않으며 서버에 도달하지 않은 클릭은 관측할 수 없습니다.

- `OFFICIAL_PMF`: 응답 시점 이전 14일 이내에 수동 분석 요청이 기록됨
- `OTHER`: 서버에서 14일 이상 관측한 응답자이며 해당 기간에 수동 분석 요청이 기록되지 않음
- `HISTORY_UNKNOWN`: 수동 분석 요청이 확인되지 않고 관측 기간이 14일 미만임

캠페인이 종료된 뒤에도 관리자 API로 기존 결과를 조회할 수 있습니다. 관리자 집계 응답에는 자유 의견과 응답자 식별자를 포함하지 않습니다.
