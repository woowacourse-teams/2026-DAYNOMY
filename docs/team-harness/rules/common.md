# 공통 Rule

- 구현 전 구현 방향과 변경·제외 범위를 공유하고 승인을 받는다.
- MVP 범위 안에서만 구현한다.
- 서비스 기획서, API 명세, ADR을 먼저 확인하고 기존 코드 구조와 네이밍을 따른다.
- 요청받지 않은 기능 추가, 리팩토링, 구조 변경을 하지 않는다.
- 불필요한 인터페이스, Mapper, Command, 추상화를 미리 만들지 않는다.
- 테스트는 비즈니스 로직, 예외 상황, 주요 사용자 흐름을 중심으로 작성한다.
- 실패한 테스트를 삭제하거나 비활성화하지 않는다.
- 민감정보, API 키, 개인정보를 코드·로그·응답·커밋에 남기지 않는다.
- 커밋 메시지는 `타입: 한국어 설명` 형식으로 작성한다.
- `main`, `dev`에 직접 커밋하지 않으며 강제 푸시를 하지 않는다.
