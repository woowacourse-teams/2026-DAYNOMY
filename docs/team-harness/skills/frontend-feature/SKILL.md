# 프론트엔드 기능 구현

1. 서비스 기획서, API 명세, 관련 ADR과 기존 페이지·기능 모듈·공통 컴포넌트를 확인한다.
2. 구현 범위와 제외 범위, 영향받는 화면·API·상태를 정리해 공유한다.
3. 구현 방향을 먼저 제안하고 승인받는다. 승인 전에는 코드 수정을 시작하지 않는다.
4. API 요청·응답 타입을 명세에 맞게 정의하고, 서버 상태와 화면 상태를 분리한다.
5. 이미 있는 공통 컴포넌트를 우선 재사용한다. 재사용이 맞지 않으면 기능 범위 안에서만 새 컴포넌트를 만든다.
6. 서버 응답을 필요한 화면 모델로 변환하고 입력 검증을 추가한다.
7. 로딩, 빈 화면, 오류 상태를 처리하고 주요 흐름 또는 복잡한 상태의 테스트를 작성한다.
8. `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test`를 실행하고, PR 전 `npm run build`를 실행한다.

승인받지 않은 화면·상태·공통화, 불필요한 전역 상태 도입, API 응답의 무검증 전파는 금지한다.
