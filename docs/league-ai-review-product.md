# 투자리그 근거 기반 AI 복기 코치 기획서

**상태:** 리그 조건부 알림·즉시 입력·복기 페이지 단일 입력기 및 실제 API 연결 구현, 모델 품질 평가 전 · **수정일:** 2026-11-02

## 제품 결정

투자리그에서 로그인한 본인의 미복기 기록이 있을 때만 고양이가 나타나 복기를 제안한다. 알림이나 고양이를 누르면 해당 기록의 작성 폼이 바로 열린다. 복기 페이지에서는 dev의 기존 기록 카드와 작성 폼을 그대로 사용하고 별도 입력기를 띄우지 않는다. 복기는 AI 없이도 작성·저장할 수 있다. 사용자가 기사 도움을 요청한 경우 관련 기사와 보조 질문을 제공하고 출처를 연결한다. 운영 복기와 같은 실제 결과·예상과 달랐던 점·다음 행동의 3항목 폼을 사용하며 AI 응답이 입력값을 바꾸지 않는다.

캐릭터는 정해진 복기 작업을 대화 형태로 안내한다. 사용자의 판단을 출발점으로 제한된 검색 도구를 실행하고, 검색 결과에 근거해 복기 작성을 돕는다. 기술 목표는 검색 증강 생성(RAG), 읽기 전용 도구 호출, 출처 검증, 품질 평가를 실제 사용자 흐름에 적용하는 것이다. 기술명은 구현 후에만 사용하며, Java용 프레임워크를 쓰면 **LangChain4j**라고 표기한다.

## 문제와 대상

현재 사용자는 보유 이유·기대 변화·판단 무효 조건을 기록하지만, 시간이 지난 뒤 어떤 자료와 비교해야 할지 직접 찾고 복기를 시작해야 한다. 단순 질문 생성만으로는 확인할 자료가 없고, AI가 사실을 만들어도 사용자가 판별하기 어렵다. 이 기능은 **판단 → 관련 자료 확인 → 복기 작성**을 한 화면에서 연결한다.

대상은 로그인한 회원의 복기 0건 투자 기록이다. 기사에서 확인한 내용을 보여줄 뿐, 기사 내용의 진실이나 투자 판단의 옳고 그름을 서비스가 판정하지 않는다.

## 사용자 경험

1. 로그인한 회원이 현재 리그 참여를 시작한 뒤 7일이 지났고, 생성 후 7일 이상 지난 미복기 기록과 집계된 성과가 있으면 고양이와 짧은 알림을 표시한다. 기록 조회 실패나 미복기 기록이 없는 경우에는 표시하지 않는다. 알림 또는 고양이를 한 번 누르면 세 항목을 한 폼에서 바로 입력할 수 있다. 리그 진입과 알림 표시만으로는 AI를 호출하지 않는다. 고양이나 바로 작성하기를 누르면 관련 기사와 질문을 자동으로 준비한다.
2. 플로팅에서는 열기 동작에 따라 자동으로, 기존 복기 페이지에서는 근거 찾기를 누를 때 서버가 판단의 마지막 저장 시각 이후 최근 90일의 DAYNOMY 발행 기사 본문을 검색한다. 조회 중이나 실패한 경우에도 직접 작성·저장을 계속할 수 있다. 접었다 다시 열어도 준비한 결과를 재사용하고, 실패 시에만 다시 찾기 버튼을 제공한다.
3. AI 질문은 기존 항목의 보조 설명으로 표시한다. 고양이 복기 창에서는 당시 판단과 참고 기사를 폼 위에서 펼쳐 확인하고, 질문의 근거 번호를 누르면 해당 기사 영역을 바로 펼친다. 일반 복기 페이지도 폼 위에서 참고 기사를 펼쳐 확인하고, PC에서는 보유 이유와 작성 폼을 나란히 표시한다. 기존 항목 이름을 바꾸거나 입력값을 채우지 않는다. 최대 5개의 근거 후보에 발행일·제목·본문 발췌·링크를 표시하고, 해당 보조 질문이 참조한 기사만 연결한다.
4. 운영과 같은 실제 결과·예상과 달랐던 점·다음 행동 세 항목을 한 작성 폼에서 입력한다. 별도 질문 단계나 최종 확인 화면을 두지 않는다. 리그의 플로팅과 복기 페이지는 모두 기존 InvestmentRecords 작성 폼을 사용한다. 플로팅에서는 작성한 항목 수를 표시하고, 입력 영역만 스크롤되게 하여 하단 저장 버튼이 입력칸을 가리지 않게 한다. 작성 중에는 중복 작성 버튼을 숨기고, 기록 설명과 저장·수정 기능은 기존 dev 구성을 따른다. 모바일에서 키보드를 자동으로 띄우지 않는다. 리그에서 접기·숨기기·나중에를 누르거나 AI 도움이 실패해도 초안을 유지한다.
5. 확정 주간 포트폴리오 성과가 있으면 주차·종가 기준일·**포트폴리오 전체** 수익률을 별도 카드에 표시한다. 특정 거래의 성과나 기사와 수익률의 인과관계로 설명하지 않는다.
6. 작성 폼에서 내용을 직접 수정하고 저장한다. 비어 있거나 500자를 넘는 항목이 있으면 해당 입력칸으로 초점을 옮긴다. 사용자가 저장하며 저장한 복기는 기존 공개 설정을 따른다. AI 요청이나 저장이 실패하거나 창을 접어도 초안은 유지된다.

**종목 관리·추가에서의 복기 알림:** 두 화면에서도 기존 투자 기록 중 미복기 기록만 고양이가 안내한다. 고양이를 누르면 같은 복기 폼과 자동 근거 찾기로 연결한다. 필수 보유 이유는 기존 종목 추가 폼의 검증에 맡기며 고양이가 별도로 작성 방법을 안내하지 않는다. 기존 종목은 추가 대상에서 제외하고, 수량·평균 매수가 비교나 수동 덮어쓰기 확인을 표시하지 않는다. 복기 완료 창을 닫으면 종목 목록을 다시 읽어 저장한 복기를 반영한다.

**자료가 없는 경우:** 최근 관련 발행 기사가 없으면 “확인할 수 있는 관련 기사가 없어요”라고 표시한다. 기사 인용 없이 저장된 판단만 바탕으로 한 질문을 제공하며, 사용자는 그대로 수동 복기를 작성할 수 있다.

## 기사·복기 알림 운영 방침

리그 등록 후 충분히 관찰한 다음 복기를 시작하도록, 최초 안내와 재안내 모두 7일을 기준으로 한다. 7일은 서버 시각 기준 연속 168시간이며 특정 요일이나 자정에 초기화하지 않는다.

| 항목 | 현재 동작 |
| --- | --- |
| 알림 대상 | 로그인한 본인의 복기 0건 투자 기록 중 생성 후 7일 이상 지난 기록. 새로 추가한 종목의 기록도 7일을 기다린다. 거래일을 과거로 입력하거나 보유 이유를 수정해도 생성 시각 기준은 바뀌지 않는다. |
| 노출 시점 | 현재 리그 참여 시작 후 7일이 지난 뒤 리그·종목 관리·종목 추가 화면을 처음 방문할 때 확인한다. 비활성 탭에서는 요청하지 않으며 푸시·메일 발송이나 시간마다 뜨는 팝업은 없다. |
| 성과 대기 | 현재 참여 기간의 유효한 거래일 성과 집계가 최소 1건 있어야 한다. 0% 기준 성과도 유효하며, 집계가 없으면 알림 주기를 소모하지 않고 다음 방문으로 미룬다. 수동 복기는 언제든 가능하다. |
| 재안내 주기 | 마지막 안내 후 7일이 지난 다음 방문에서 한 번 안내한다. 여러 기록은 한 알림에 모으며, 새로고침·화면 이동·다른 기기에서도 계정 단위 서버 이력으로 중복 안내를 막는다. |
| 닫기·나중에 | 알림 닫기·접기·숨기기·나중에는 해당 안내를 닫은 시점부터 7일 뒤로 미룬다. 같은 안내의 재요청은 기간을 중복 연장하지 않는다. 저장 실패 시 재시도할 수 있게 알린다. 접거나 숨긴 초안은 현재 화면에서 유지하고 고양이로 다시 작성할 수 있다. |
| 재가입 | 리그 참여 종료 후 재가입하면 새 참여 시작부터 다시 7일을 기다린다. 이전 참여의 알림 주기는 초기화한다. |
| 완료 처리 | 저장한 복기 기록은 알림 대상에서 제외한다. 남은 미복기 기록은 이어서 작성할 수 있다. 복기 페이지 자체에는 중복 고양이 입력기를 띄우지 않는다. |
| AI 실행 | 고양이에서 작성 창을 열 때 자동으로 준비하고, 일반 복기 페이지에서는 근거 찾기를 눌렀을 때 실행한다. 페이지 진입·알림 노출만으로는 AI를 호출하지 않는다. 같은 창을 접었다 다시 열면 진행 중 요청·결과를 재사용한다. |
| 기사 범위 | 해당 자산에 연결된 DAYNOMY 발행 기사 우선. 보완 검색 결과도 제목·본문에서 자산명을 확인한다. 최근 90일 중 판단 최종 저장 시각 이후 기사만 최대 5개 제공한다. |
| 기사 표시 | 제목·발행일·발췌·내부 링크는 실제 발행 기사에서 가져온다. AI는 복기 질문과 기사 참조 ID만 생성한다. 확인 가능한 기사가 없으면 가상 기사를 만들지 않고 기사 없음으로 표시한다. |
| AI 요청 한도 | 회원별 서울 날짜 기준 하루 10회 시도, 동시 1건. 현재는 서버 인스턴스별 메모리 제한이므로 재시작·다중 인스턴스에 걸친 영속·전역 상한은 아니다. |

화면에 실제 표시하기 직전에 서버에서 안내 차례를 선점한다. 네트워크 단절이나 화면 이탈로 안내를 보지 못한 경우에도 이미 선점한 7일 주기는 유지될 수 있다. 알림 확인에 실패하면 화면은 그대로 사용하고, 다음 방문에서 다시 확인한다.

## 첫 버전의 범위

| 포함                                                   | 제외                                               |
| ------------------------------------------------------ | -------------------------------------------------- |
| 복기 0건인 본인 기록에서 명시적 요청 시 검색·질문 생성 | 상시 대화·대화 기억·다른 회원 기록 분석            |
| DAYNOMY 발행 기사 본문 검색과 내부 기사 링크           | 실시간 웹 검색, 외부 게시물 본문 추정, 자동 크롤링 |
| 기사 원문 발췌·발행일·질문별 기사 참조                 | AI가 근거 없는 사실을 단정하는 요약                |
| 확정 주간 포트폴리오 성과 별도 표시                    | 종목별 성과 귀속·수익률 예측·매매 추천             |
| AI 실패·자료 없음·수동 작성 경로와 초안 보존           | 자동 복기 저장·공개·거래 실행                      |
| 검색 정확도·출처 유효성·복기 전환 평가                 | 첫 버전의 벡터 DB·임베딩 인덱스                    |

검색 결과와 질문은 요청 화면에서만 사용한다. 계정에는 사용자가 직접 저장한 복기와 알림 주기 관리 이력을 남긴다. AI 질문과 검색 결과는 저장하지 않는다.

## 수용 기준

- 인증된 본인 기록만 처리한다. 이미 복기가 있으면 AI 호출 전에 종료하고 화면은 기록을 다시 읽는다.
- 모든 근거 카드는 요청 당시 발행 상태인 기사로 연결되며, 발췌는 실제 기사 본문의 연속된 문자열이다. 삭제·비공개·기간 밖 기사는 포함하지 않는다.
- 질문이 기사 내용에 기대면 해당 기사 ID가 응답의 근거 목록에 있어야 한다. 자료가 없으면 기사나 사건·수치·날짜를 지어내지 않는다.
- 기사 내용은 **관련 자료**로 제시한다. 사실의 최종 검증, 특정 판단의 성패, 매수·매도 지시는 하지 않는다.
- 확정 성과가 없어도 검색과 질문은 동작한다. 기사와 성과가 모두 없더라도 사용자는 수동 복기를 저장할 수 있다.
- 요청 실패·시간 초과·기록 전환·질문 닫기·저장 실패 시 사용자의 입력 초안이 유지된다.
- 로그와 분석 이벤트에는 사용자 판단 원문·AI 질문·기사 발췌·수익률·회원 식별자를 기록하지 않는다.

## 성과와 품질 평가

**제품 지표:** GA4·PostHog에서 알림 노출→복기 시작→AI 근거 준비·기사 확인→복기 저장 전환을 확인하고, 알림 노출 후 7일 이내 리그 재방문율도 본다. 근거 카드가 제시된 편집기의 첫 복기 저장 비율을 기존 수동 작성률과 비교한다. 회원 식별자를 보내지 않아 분석의 재방문은 동일 브라우저의 익명 식별 기준이며, 계정 단위 기기 간 중복 방지는 서버 정책에만 적용한다. 노출→요청→근거 확인→저장 전환, 자료 없음 비율, 생성 성공률, p95 지연 시간, 호출당 비용도 본다. 단순 전후 비교로 인과 효과를 주장하지 않는다.

**검색·생성 지표:** 가상 판단과 발행 기사로 만든 고정 평가셋에서 Recall@5, 질문의 유효한 기사 참조 비율, 근거 없는 사실 주장 비율, 매매 지시 발생률을 측정한다. 출시 후보의 기준은 Recall@5 80% 이상, 잘못된 기사 ID 0건, 근거 없는 사실 주장 5% 이하, 매매 지시 0건이다. 작은 평가셋의 수치는 실제 사용자 품질을 보증하지 않으므로 소규모 사용성 검증을 병행한다.

## 출시 전 확인 사항

기사 본문은 DAYNOMY의 발행 콘텐츠만 사용하며, 기사에 원출처가 있으면 사용자가 기사에서 확인할 수 있게 한다. 투자 판단 원문이 외부 AI에 전송되므로 안내 문구와 개인정보처리방침의 처리 범위·보관 정책을 운영자가 확인해야 한다. 공개 프로필이나 검색 결과 API에 개인 질문과 복기 초안을 추가하지 않는다.

**현재 브랜치 상태:** feature/BE/769의 근거 검색·LangChain4j 도구 호출·출처 검증과 feature/FE/768의 리그 조건부 알림·직접 입력·실제 조회/저장 API 연결이 구현됐다. 복기용 목업 서버·가상 기사·체험 경로는 제거했으며 실제 인증과 백엔드 API를 사용한다. 실제 계정의 연동 점검과 30건 이상 가상 사례의 모델 품질 평가는 남아 있다. 상세 계약은 [기술명세서](./league-ai-review-technical.md)에 정의한다.
