# 리그 접근성 개선 리포트

검증일: 2026-10-15

## 핵심 영역과 범위

기존 리그 컴포넌트의 웹 접근성을 개선했다.

- 주간 순위 조회, 주차·페이지 변경, 투자자 상세 지표 팝업
- 공개 투자자 프로필, 팔로우·팔로잉 취소, 주간·일별 수익률
- 내 프로필, 팔로잉 목록
- 리그 종목 관리, 원본 포트폴리오에서 종목 선택, 보유 이유 작성, 삭제 확인
- 프로필 설정과 리그 참여 동의, 투자 기록의 결과 복기

`/league/*`는 기존 준비 중 안내에 연결되어 있다. 라우트, API, 공개 정책은 변경하지 않는다.

## 문제와 개선 결과

| 영역                | 개선 전                                                               | 개선 후                                                                                 |
| ------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 페이지 이동         | 제목이 공통으로 남고 새 화면의 시작점에 초점이 가지 않음              | 각 화면의 문서 제목을 설정하고 주 제목으로 초점 이동. 비동기 프로필은 조회 완료 후 이동 |
| 반복 버튼           | 결과 복기 버튼만으로 어느 기록인지 구별하기 어려움                    | 종목·거래일·기록 종류를 포함한 이름 제공                                                |
| 팔로우              | 투자자와 선택 상태를 버튼 의미로 전달하지 않음                        | 투자자 이름과 동작을 제공하고 `aria-pressed`로 상태 전달                                |
| 보유 이유·복기 입력 | 공백 입력 오류가 입력과 연결되지 않고 초점이 제출 버튼에 남음         | `aria-invalid`, `aria-describedby`를 제공하고 첫 미작성 입력으로 이동                   |
| 저장 실패           | 오류가 표시되어도 키보드 초점으로 바로 확인하기 어려움                | 오류 안내에 초점 이동. 초안과 기존 재시도 요청 키 유지                                  |
| 작성 종료·삭제 확인 | 폼이 사라지면 초점 위치를 잃을 수 있음                                | 저장·취소 후 해당 버튼 복귀. 삭제 확인은 취소에 초점, 삭제 완료는 기록 영역으로 이동    |
| 순위 페이지 변경    | 로딩 중 페이지 버튼이 사라져 초점 손실                                | 갱신 후 페이지 안내로 이동. 순서 목록의 시작 번호도 갱신                                |
| 공유 종목 선택      | 추가 불가 사유와 선택 상태 변경을 바로 인지하기 어려움                | 선택·보유 이유 안내를 상태 메시지로 전달하고 입력·추가 버튼에 연결                      |
| 닉네임              | 비어 있으면 저장 버튼이 비활성화되어 필수 입력 검증을 실행하기 어려움 | 기본 `required`·`pattern` 검증으로 잘못된 입력에 초점 이동. 참여 준비 조건은 유지       |
| 선택된 조회 단위    | 글자 대비 4.483:1                                                     | 기존의 더 진한 버튼 색을 사용해 본문 기준 4.5:1 충족                                    |

기존의 네이티브 버튼·링크·라벨·fieldset·dialog, 수익률 표의 caption과 행·열 제목, 장식 이미지 처리는 유지했다. 의미를 보충하는 곳에만 ARIA를 추가했다.

## 검증 과정

### 회귀 테스트와 빌드

`frontend`에서 다음 명령이 모두 통과했다.

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

- 단위 테스트 37개, UI 테스트 402개: 총 439개 통과
- 리그 테스트는 화면 제목·초점, 팔로우 상태, 폼 오류 연결, 저장 실패 시 초안 보존, 저장·취소·삭제 확인 후 초점 복귀, 페이지 변경을 검증한다.
- 기존의 원본 포트폴리오 보존·공개 범위·API 응답 검증 테스트도 유지한다.
- 배포 빌드의 리그 안내 브라우저 테스트 3개가 통과했다. 실제 리그 코드와 스타일이 배포 번들에서 제외되는 것도 확인했다.

### 실제 브라우저

운영의 준비 중 페이지 대신 실제 컴포넌트를 임시 검증 화면에서 렌더링했다. Chrome과 API 계약에 맞는 테스트 응답을 사용했으며 실제 계정·투자 데이터는 변경하지 않았다.

1. Tab·Enter로 상세 지표를 열고 팝업 내부 이동, Esc 닫기, 원래 버튼 복귀를 확인했다.
2. 다음 순위 페이지로 이동한 뒤 페이지 안내 초점과 목록 시작 번호를 확인했다.
3. 팔로우·취소의 이름과 선택 상태, 일별 수익률 표의 접근 가능한 이름을 확인했다.
4. 보유 이유의 공백 오류, 저장 실패 후 초안 유지, 재시도 저장, 삭제 확인·취소·완료의 초점 이동을 확인했다.
5. 공유 종목 선택 안내와 패널 취소 후 제목 복귀를 확인했다.
6. 복기의 첫 미작성 항목 초점과 오류 상태, 저장 후 작성 버튼 복귀를 확인했다.
7. 닉네임의 필수 입력·공백 검증, 내 프로필 제목, 팔로잉 링크를 확인했다.
8. 너비 390px에서 주요 6개 화면의 가로 넘침이 없음을 확인했다.

데스크톱·모바일의 14개 화면 상태에서 보이는 텍스트 252개를 측정했다. 일반 텍스트 4.5:1, 큰 글자 3:1 미만은 없었다. 이 측정은 사용한 테스트 데이터와 화면 상태에 한정되며 모든 데이터·상태의 자동 접근성 인증을 뜻하지 않는다.

## 남은 증빙과 검증

- 실제 VoiceOver 또는 NVDA로 주요 기능을 사용하며 음성 안내·읽기 순서 확인
- 리그 개선 전·후를 같은 시나리오로 녹화한 비교 영상
- 운영 라우트 공개 시 실제 인증·API와 통합한 사용자 흐름 확인

현재 결과는 코드 개선, 회귀 테스트, Chrome 키보드·화면 검증까지 완료한 상태다. 스크린리더 실기 및 리그 비교 영상까지 완료했다고 제출해서는 안 된다.
