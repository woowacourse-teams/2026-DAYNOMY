# Frontend Rule

- KISS, YAGNI, DRY 원칙을 따른다. 컴포넌트와 Hook의 책임을 분리하되, 재사용을 이유로 과도한 공통화나 추상화를 만들지 않는다.
- 페이지, 기능 모듈, 공통 컴포넌트의 책임을 구분한다.
- UI와 비즈니스 로직을 분리하고 복잡한 로직은 Hook 또는 기능 모듈로 관리한다.
- 서버 상태와 클라이언트 상태를 구분하며 불필요한 전역 상태를 만들지 않는다.
- API 요청·응답 타입은 API 명세와 백엔드 DTO 이름·필드명을 기준으로 정의한다.
- 서버 응답은 화면에 필요한 형태로 변환해서 사용한다.
- 이미 있는 공통 컴포넌트와 유틸리티를 먼저 확인하고, 한 번만 쓰는 컴포넌트를 과도하게 추상화하지 않는다.
- 로딩, 빈 화면, 오류 상태와 기본적인 반응형·접근성을 처리한다.
- 사용자 입력을 검증하고 주요 사용자 흐름과 복잡한 상태 처리를 테스트한다.
- TypeScript 기준은 `frontend/README.md`의 `TypeScript와 외부 입력`을 따른다. 외부 값을 검증하기 전에 `String()`·`Number()`로 강제 변환하거나 응답 타입으로 단언하지 않는다. enum은 원래 타입과 허용값을 함께 검사한다.
- 런타임 가드를 변경하면 정상·누락·null·알 수 없는 enum·타입이 다른 응답을 검증한다. 검증 실패를 빈 정상 데이터로 바꾸지 않고 기존 오류·재시도 경로로 전달한다.
