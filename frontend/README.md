# DAYNOMY Frontend

사용자가 보유 자산과 거래를 등록하고, **포트폴리오 AI 분석 결과와 근거를 확인**할 수 있는 React 애플리케이션입니다.

현재 자산 구성, 종목별 영향, 이전 분석 이후의 변화와 분석 출처를 하나의 흐름으로 제공합니다. 경제 콘텐츠 탐색, 투자 기록과 복기, 투자 리그 화면도 함께 제공합니다.

> 전체 프로젝트 소개는 [루트 README](../README.md)를 확인해 주세요.

## 주요 사용자 경험

| 영역            | 주요 경험                                                |
| --------------- | -------------------------------------------------------- |
| 포트폴리오 분석 | 전체·종목별 영향, 근거와 변경 내용 확인, 비회원 체험     |
| 자산과 거래     | 국내·미국 주식·ETF, 거래 기록, CSV 일괄 편집과 자산 추이 |
| 경제 콘텐츠     | 보유 종목 소식, 인물·외부 자료와 통합 검색               |
| 투자 리그       | 주간 성과, 공개 투자자, 복기 알림과 기사 기반 AI 질문    |
| 이메일 알림     | 중요 종목 자동 분석과 구독 설정                          |

## 포트폴리오 분석 화면

| 상태                | 화면 동작                               |
| ------------------- | --------------------------------------- |
| `EMPTY`             | 최초 분석 요청 안내                     |
| `READY`             | 저장된 최신 분석과 근거 표시            |
| `PORTFOLIO_CHANGED` | 자산 변경 안내와 새로운 분석 요청 제공  |
| `PROCESSING`        | 진행 상태를 표시하고 저장 상태 재조회   |
| `RECHECK_REQUIRED`  | 기존 결과를 유지하며 근거 재확인 안내   |
| `FAILED`            | 기존 결과가 있으면 유지하고 재시도 제공 |

회원 분석 결과는 서버에 저장합니다. 단순 조회에는 AI 호출이 발생하지 않으며, 새로운 분석과 최신 근거 재확인은 별도 사용자 동작으로 구분합니다.

비회원의 보유 자산과 거래 기록은 현재 탭의 `sessionStorage`에 임시 저장합니다. 분석은 한 번 체험할 수 있으며 로그인 계정의 포트폴리오로 자동 이전하지 않습니다.

## 로컬 실행

Node.js 20.19 이상 또는 22.12 이상이 필요합니다.

```bash
npm install
npm run dev
```

개발 서버는 `http://localhost:5173`에서 실행됩니다.

## 백엔드 연결

로컬 백엔드는 기본적으로 `http://localhost:8080`을 사용합니다.

`VITE_API_BASE_URL`이 비어 있으면 Vite가 `/api`, `/oauth2`, `/login/oauth2`를 로컬 백엔드로 전달합니다. 직접 연결하려면 다음 값을 설정합니다.

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

Google OAuth의 로컬 리디렉션 URI는 `http://localhost:8080/login/oauth2/code/google`입니다. 쿠키 인증을 위해 `localhost`와 `127.0.0.1`을 혼용하지 않습니다.

## 로딩 성능 관리

소개 첫 장면은 `overview.png` 캡처 원본과 픽셀이 같은 무손실 `overview.webp`를 제공합니다. `scripts/capture-landing.mjs`로 원본을 갱신할 때 WebP도 함께 갱신합니다.

첫 방문 `/welcome`, 비로그인 뉴스 상세 `/news/:id`, 로그인 후 포트폴리오 `/`를 관리 대상으로 둡니다. FCP는 첫 콘텐츠 표시, LCP는 화면의 가장 큰 콘텐츠 표시, TTFB는 문서의 첫 바이트 수신까지입니다. 소개의 4.2초 인트로는 유지하므로 LCP와 별도로 인트로 종료 시간을 기록합니다. 뉴스는 본문, 포트폴리오는 저장 자산과 계산된 잔고가 나타나야 이용 준비가 된 것으로 봅니다.

| 예산                           | 데스크톱           | 모바일 제한 조건 | 이유                                         |
| ------------------------------ | ------------------ | ---------------- | -------------------------------------------- |
| FCP / LCP                      | 1.0초 / 1.5초      | 1.8초 / 2.5초    | 첫 콘텐츠와 핵심 콘텐츠의 대기 제한          |
| TTFB                           | 0.8초              | 0.8초            | 네트워크·서버 응답을 프론트 표시 시간과 분리 |
| 뉴스 / 포트폴리오 이용 준비    | 1.5초 / 2.0초      | 2.5초 / 3.0초    | API를 포함한 실제 화면 준비 확인             |
| 소개 인트로 종료               | 6.0초              | 7.0초            | 의도한 4.2초 연출과 자원 로딩을 함께 관리    |
| 첫 진입 JS / CSS / 전체 전송량 | 200 / 60 / 500 KiB | 동일             | 필요한 화면만 다운로드하고 재증가 감지       |

이 목표는 팀의 실험 예산이며 전체 사용자 합격 판정이 아닙니다. [LCP 기준](https://web.dev/articles/lcp)을 참고하되 서비스 이용 준비 시점도 별도로 확인합니다. 압축 전 번들 크기와 전송량을 혼용하지 않습니다.

페이지는 `React.lazy`로 분리하고 공통 인증·내비게이션은 유지합니다. 파일을 받는 동안 본문 높이를 확보한 로딩 안내를, 실패하면 기존 오류 경계를 표시합니다. 해시 자산의 장기 캐시와 이전 배포 자산 보관 정책은 유지합니다.

`npm run build`의 production 빌드로 소개·뉴스·포트폴리오를 데스크톱/모바일 조건과 빈 캐시/재방문으로 나눠 각 5회 측정합니다. Lighthouse, Network, Coverage, 번들 분석과 전후 중앙값·최솟값·최댓값을 보고서에 보관합니다. 운영 결과는 해당 커밋 배포 후 `staff.daynomy.com`에서 별도 확인하며, 로컬 API 고정 실험의 TTFB를 운영 서버 결과로 해석하지 않습니다.

## TypeScript와 외부 입력

타입 선언과 단언은 JavaScript로 빌드할 때 사라집니다. `request<T>`의 `T`는 서버 응답을 검사하지 않습니다. 외부 JSON은 `unknown`에서 검사한 뒤 화면 모델로 전달하며, 검사 이후의 내부 props·상태에는 같은 검증을 반복하지 않습니다.

| 구분   | 기준과 이유                                                                                                                      | 강제 방법                                                               |
| ------ | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 스타일 | Props·DTO·일반 객체는 `type` 우선. 선언 병합이 필요한 환경 확장에는 `interface`. 동작 차이가 없는 기존 선언은 일괄 변경하지 않음 | 리뷰·LLM 규칙                                                           |
| 스타일 | 지역 값과 인라인 이벤트는 추론. 재사용 핸들러는 `ChangeEvent<HTMLInputElement>` 등 실제 요소 타입, 공개 함수·Props 계약은 명시   | 추론 가능한 코드의 중복 선언은 리뷰에서 판단                            |
| 안전성 | 앱·Node·테스트 `strict`. null·unknown은 분기 후 사용                                                                             | `tsc -b`, 테스트는 앱 설정 상속                                         |
| 안전성 | `any`와 `@ts-ignore`·`@ts-nocheck`로 검사 우회 금지. `@ts-expect-error`는 이유 10자 이상과 함께 사용                             | Oxlint error; 불필요해진 expect-error는 tsc 오류                        |
| 안전성 | `as const`는 허용. `as`는 검사 후 추론 한계에만 사용. 앱의 `!`는 존재 확인 우선; DOM·테스트의 존재 보장은 근거가 있어야 함       | 단언의 타당성은 리뷰·LLM 규칙. 린트가 모든 잘못된 단언을 찾는 것은 아님 |
| 안전성 | enum은 `typeof value === 'string'`과 허용값을 함께 확인. 검사 전에 `String(value)`를 쓰면 `['READY']`도 통과하므로 금지          | 경계 테스트·리뷰·LLM 규칙                                               |

런타임 검증 범위:

| 경계                                        | 검사 및 실패 정책                                                         | 범위의 이유                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 인증 프로필·CSRF·오류 응답                  | 역할·필수 필드·타입 검사. 인증/오류 처리 경로로 전달                      | 권한·요청 처리에 직접 영향                                                                                    |
| 포트폴리오 계산·AI 분석·거래, 종목 검색     | 필수 필드·숫자·enum·중첩 목록 검사. 실패는 기존 오류·재시도 UI            | 잘못된 금액·분석을 정상으로 보여주지 않음                                                                     |
| 공개 리그·일별 기록·AI 복기 질문, 인기순    | enum 원래 타입과 값, 기존 날짜·누적 수익률·질문·근거·점수 검증 유지       | 순위와 데이터 상태를 잘못 해석하지 않음                                                                       |
| 뉴스·관리자·검색, 브라우저 저장소·CSV       | 각 기능의 기존 가드/파서 유지. 손상된 저장 데이터는 기존 정책에 따라 복구 | API 외에도 이전 버전·사용자 입력이 들어오는 경계                                                              |
| 피드백 등록·삭제, 로그아웃 등 `void` 응답   | HTTP 실패와 공통 오류는 검사하되 성공 응답 본문은 검증하지 않음           | 화면에서 성공 본문을 사용하지 않는 계약                                                                       |
| 검증된 내부 props·계산값                    | 추가 런타임 검증 없음                                                     | 외부 입력이 아닌 구간은 strict와 테스트로 확인                                                                |
| 그 밖의 서버 DTO·이번 변경 밖의 선택적 필드 | 기존 계약과 오류 처리를 유지하고 전수 스키마 검증은 추가하지 않음         | 이번 재방문은 확인된 enum 변환 결함에 집중. 잘못된 응답이 발견되거나 금액·권한·분석에 쓰이면 경계 검증을 추가 |

누락·null·추가 필드는 API 계약에 따라 구분합니다. 예를 들어 저장 분석의 과거 응답에서 생략 가능한 `summaryStatus`는 허용하고, 필수 `status` 누락·null·배열·미등록 문자열은 거부합니다. 검증 오류를 빈 성공 응답으로 대체하지 않습니다. 기존 가드를 보완할 수 있어 새 검증 라이브러리는 추가하지 않았습니다.

검사는 로컬 `npm run lint`·`npm run typecheck`, PR의 `.github/workflows/frontend-ci.yml`에서 각각 수행합니다. 로컬 `npm run build:development`·`build:production`도 `tsc -b`가 성공한 뒤 Vite를 실행합니다. CI·CD는 독립 Typecheck 단계 성공 후 Vite를 직접 실행해 중복 검사를 피합니다. Vite 변환 자체를 타입 검사로 간주하지 않습니다. 저장소의 `Frontend checks` 필수 체크 설정이 유지되어야 실패한 PR의 병합이 차단됩니다.

## 공개 HTML과 검색 노출

프론트 컨테이너의 Node 서버는 공개 URL의 첫 HTML을 생성하고, 이후 화면 조작은 React 애플리케이션이 담당합니다.

- `/welcome`, `/news`, 발행된 뉴스와 종목 상세는 검색 노출 대상입니다.
- 공개 투자자 프로필은 공유 미리보기를 제공합니다.
- 로그인 후 화면과 관리자 화면은 검색 대상에서 제외합니다.
- 공개 페이지의 제목, 설명, canonical과 공유 메타데이터를 서버에서 생성합니다.
- robots와 sitemap은 공개 정책에 맞춰 제공합니다.

상세한 결정 배경은 [공개 HTML ADR](./docs/adr/261027-페이지별-렌더링과-공개-HTML.md)을 확인해 주세요.
