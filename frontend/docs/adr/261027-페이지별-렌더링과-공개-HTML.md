# 페이지별 렌더링과 공개 HTML

상태: 채택 (2026-10-27, 이슈 #690)

## 현재 구조와 요구

React Router의 `BrowserRouter`와 Vite 빌드를 사용한다. 기존 프론트 컨테이너는 모든 SPA 경로에 같은 `index.html`을 반환했다. 이 HTML의 `#root`는 비어 있고, 뉴스·종목·프로필 데이터는 브라우저가 공개 API에서 가져왔다. 호스트 Nginx는 화면 요청을 프론트 컨테이너로, `/api`와 OAuth 요청을 백엔드로 전달한다. 브라우저에서 설정한 `document.title`은 첫 HTML의 공유 메타데이터가 아니다.

| 페이지                                   | 공개 범위와 갱신                          | 검색·공유 필요    | 첫 HTML 방식                                        | 캐시·재생성                                                         |
| ---------------------------------------- | ----------------------------------------- | ----------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| `/`                                      | 개인화된 포트폴리오 또는 비회원 시작 화면 | 검색 제외         | CSR 셸                                              | HTML `no-cache`, 개인 데이터는 기존 API 정책                        |
| `/welcome`                               | 모두에게 같은 서비스 소개, 배포 때 변경   | 검색·공유         | 서버의 정적 본문·메타데이터                         | HTML `no-store`; 배포 즉시 갱신                                     |
| `/news`                                  | 발행 뉴스가 수시로 변경                   | 검색·공유         | 서버가 최신 발행 뉴스 20건의 링크와 메타데이터 생성 | HTML `no-store`; 요청마다 공개 API 조회                             |
| `/news/:id`                              | 발행·수정·삭제 가능                       | 검색·공유         | 서버가 발행 뉴스 본문과 메타데이터 생성             | HTML `no-store`; 요청마다 공개 API 조회, 삭제 시 404                |
| `/stocks/:assetId`                       | 공개 종목 자료가 수시로 변경              | 검색·공유         | 서버가 종목명과 공개 자료 링크 생성                 | HTML `no-store`; 공개 자료가 없는 종목은 `noindex`, 없는 종목은 404 |
| `/league/:publicId`                      | 사용자가 공개를 해제할 수 있는 프로필     | 공유만, 검색 제외 | 서버가 공개 프로필 이름·소개만 생성                 | HTML `no-store`; 요청마다 공개 API 조회, 비공개 전환 시 404         |
| `/news/today`·`/news/contents`·`/people` | 공개 목록이지만 개별 검색 대상에서 제외   | 검색·공유 제외    | 기존 CSR 셸, `noindex`                              | HTML `no-cache`; 화면 데이터는 기존 API 조회                        |
| 로그인·포트폴리오·관리·검색 화면         | 계정 또는 URL 상태에 따라 변경            | 검색·공유 제외    | 기존 CSR 셸, `noindex`                              | HTML `no-cache`; 민감한 데이터는 HTML에 포함하지 않음               |

`/welcome`을 검색 가능한 랜딩 URL로 정했다. `/`는 로그인과 브라우저 상태에 따라 다른 화면이므로 검색 대상으로 삼지 않는다. 공개 프로필은 URL을 알면 볼 수 있지만 공개 취소 가능성을 고려해 `noindex`로 둔다. 개발·팀원 도메인은 모든 페이지에서 검색을 차단한다.

## 검토한 방식

| 방식                  | 초기 로딩·사용자 조작             | 검색 노출 구조                   | 공유 미리보기                   | 서버 비용·운영 복잡도                               | 판단                          |
| --------------------- | --------------------------------- | -------------------------------- | ------------------------------- | --------------------------------------------------- | ----------------------------- |
| 현행 CSR              | 셸이 먼저 보이고 이후 API 조회    | JavaScript 미실행 시 본문 없음   | 경로별 메타데이터 없음          | 가장 낮음                                           | 공개 URL 요구를 충족하지 못함 |
| 전체 SSR              | 첫 본문 제공, 수화 작업 필요      | 공개 본문을 첫 HTML에 제공       | 경로별 메타데이터 가능          | 상시 렌더링 서버와 React 브라우저 코드 전환         | 현재 범위에 과함              |
| 전체 SSG              | 정적 첫 본문이 빠름, 조작은 CSR   | 빌드 시점 콘텐츠만 검색 가능     | 빌드 시점 메타데이터            | 제공 비용은 낮지만 발행·공개 변경마다 재빌드·재배포 | 동적 뉴스·프로필에 맞지 않음  |
| 공개 HTML + CSR(혼합) | 공개 첫 본문 제공, 기존 조작 유지 | 대상 URL의 본문을 첫 HTML에 제공 | 대상 URL별 메타데이터           | 공개 API를 요청마다 조회하는 작은 HTTP 서버         | 선택                          |
| 네이티브 앱           | 앱 초기 설치·시작 비용 추가       | 웹 URL 검색 문제는 별도로 남음   | 웹 링크 미리보기 별도 구현 필요 | 앱 개발·배포 경로 추가                              | 제외                          |

선택한 방식은 User-Agent에 따라 다른 내용을 주지 않는다. 모든 요청자에게 같은 공개 본문·메타데이터를 전달하고, JavaScript가 실행되면 기존 React 앱이 `#root`를 다시 그린다. 공개 데이터의 첫 HTML 생성에는 `/api/news`, `/api/assets/{id}/contents`, `/api/league/investors/{publicId}`를 사용하고, sitemap에는 `/api/contents/assets`의 공개 자료가 있는 종목 ID를 사용한다. API 요청에 브라우저 쿠키를 전달하지 않으며 응답에서 필요한 공개 필드만 HTML로 만든다. 텍스트·URL은 이스케이프 또는 검증한다.

## 검색·공유와 운영 정책

- 공개 HTML에 고유한 제목·설명·canonical·Open Graph URL·제목·설명·이미지를 넣는다. 뉴스 이미지가 없거나 사용할 수 없으면 공개 기본 이미지를 쓴다. canonical의 도메인은 배포 환경의 `SITE_ORIGIN`에서 고정하며 요청의 `Host` 값으로 만들지 않는다.
- `robots.txt`는 운영 사용자 도메인에 sitemap을 알리고 크롤링을 허용한다. 검색 제외 화면은 첫 HTML의 `noindex`로 처리해 크롤러가 그 지시를 읽을 수 있게 한다. 개발·팀원 도메인은 전체 차단한다. `sitemap.xml`은 `/welcome`, `/news`, 발행 뉴스 URL과 공개 자료가 하나 이상 있는 종목 URL을 포함하며 서버 메모리에서 5분마다 다시 만든다. 삭제된 뉴스·종목 자료의 URL이 sitemap에 최대 5분 남아도 원본 페이지는 즉시 404 또는 `noindex`다. 프로필은 공개 취소가 가능하므로 sitemap에 넣지 않는다. 한 파일의 URL 상한은 50,000개다. 그 이상은 sitemap index로 확장한다.
- 백엔드와 프론트엔드는 별도로 배포된다. 새 종목 목록 API가 아직 없는 경우에는 기존 뉴스 sitemap을 제공하고, 다음 5분 갱신에서 종목 URL을 다시 조회한다.
- 잘못된 공개 ID·없는 뉴스·비공개 프로필은 HTTP 404와 `noindex`를 반환한다. 공개 API 장애는 503을 반환하며, 비공개 데이터나 이전 응답을 대신 보여주지 않는다.
- 공개 HTML은 매 요청 다시 생성하고 CDN·공유 캐시에 저장하지 않는다. 서버 호출과 브라우저의 기존 API 호출이 중복될 수 있다. 이 비용은 배포 후 응답 시간과 공개 API 트래픽으로 확인하고, 필요할 때 공개 뉴스에만 짧은 캐시를 도입한다. 프로필은 공개 취소 즉시 반영하기 위해 캐시하지 않는다. 해시된 자산의 기존 장기 캐시는 유지한다.
- 프론트 컨테이너는 Node HTTP 서버로 HTML과 정적 파일을 제공한다. 호스트 Nginx의 프록시·해시 자산 보관·무중단 전환은 유지한다. 컨테이너는 `API_ORIGIN`을 통해 같은 환경의 공개 API를 호출한다. 공개 URL의 가용성은 이 경로에 의존한다.

Google은 JavaScript를 렌더링할 수 있지만 첫 HTML 본문이 없는 앱은 추가 렌더링을 거치며, JavaScript를 실행하지 않는 크롤러도 있다. sitemap은 발견 힌트이며 검색 결과 노출을 보장하지 않는다. 참고: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Google sitemap 지침](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## 검증

로컬 통합 테스트에서 JavaScript 실행 없이 첫 HTTP 응답의 본문·메타데이터·404·robots·sitemap·비공개 제외를 확인했다. 실제 빌드 컨테이너에서 `/welcome`, 공개 뉴스 상세의 본문·Open Graph, 해시 자산 캐시, 빠른 종료 신호 처리를 확인했다. 기존 무중단 배포·롤백 검사는 통과했다.

배포 후 운영 URL의 실제 공유 플랫폼 미리보기와 검색 엔진 URL 검사 결과는 아직 확인하지 못했다. HTML 구조의 검색 가능성과 실제 색인·노출은 서로 다른 결과이며, sitemap 등록도 색인을 보장하지 않는다. 첫 HTML 생성은 공개 API에 의존하므로 배포 후 응답 시간과 API 트래픽을 측정해야 한다.
