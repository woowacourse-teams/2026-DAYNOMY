# PMF 설문 연동 계약 v2 — FE #805 / 별도 BE 이슈

상태: 사용자 승인 정책을 FE에 반영했다. **이 API는 아직 별도 BE 구현이 필요하다.** 이전 두 단계 POST/PATCH 계약은 아래 단일 응답 POST 계약으로 대체한다. 전체 동작 정책은 [pmf-survey-policy.md](./pmf-survey-policy.md)를 따른다.

## 공통 규칙

- JSON 응답, 쿠키 인증/익명 세션, 기존 `/api/auth/csrf` 발급 규칙을 따른다. 사용자 ID나 공식 PMF 집계 여부를 클라이언트 입력으로 받지 않는다.
- 일반 사용자에게도 설문을 보여주고, 응답 시점 최근 2주 내 포트폴리오 분석 버튼 클릭 여부를 서버가 기록해 공식 PMF/기타/이력 확인 불가를 나눠 집계한다. 기존 팀원 제외 정책을 적용한다.
- 회원은 사용자별 방문 이력으로, 비회원은 익명 식별자와 방문 세션 이력으로 첫 방문을 판정한다. 로그인 직후라고 첫 방문으로 단정하지 않는다.
- 숨김과 중복 응답은 `설문 캠페인 + 응답자` 단위로 관리한다. 쿠키 삭제·기기 변경 비회원을 동일인으로 보장하지 않는다.
- FE는 판정 로딩·오류·잘못된 형식·401/403/404에서 팝업을 표시하지 않는다. 응답 본문을 URL·분석 이벤트·브라우저 저장소에 남기지 않는다.

## GET `/api/pmf-surveys/current`

```json
{
  "surveyId": 805,
  "eligible": true,
  "responseId": null,
  "isFirstVisit": false,
  "hiddenUntil": null
}
```

- 활성 설문이 없으면 `204 No Content`. 예시 ID 805는 이슈 번호와 별개인 설문 ID 예시다. ID는 양의 안전 정수다.
- `eligible`: 캠페인·팀원 제외 등 노출 가능 여부. 공식 PMF 집계 대상 여부와 다르다.
- `responseId`: 기응답 ID 또는 null. 응답이 있으면 FE는 다시 묻지 않는다.
- `isFirstVisit`: 현재 세션 이전의 방문 기록이 없는지. FE는 true인 사용자의 최초 대시보드를 보류하고, 현재 세션에서 다른 서비스 화면을 방문한 뒤 복귀하면 노출한다.
- `hiddenUntil`: 숨김 만료 시각 또는 null. RFC3339 오프셋 포함 문자열(예: `2026-11-06T00:00:00+09:00`). 서버의 숨김 기한이 남아 있으면 로컬 저장소가 비어 있어도 노출하지 않는다.
- FE에서 최초 방문 판정이나 숨김 기한을 확인할 수 없는 형식은 노출하지 않는다.

## POST `/api/pmf-surveys/{surveyId}/responses`

```json
{ "answer": "VERY_DISAPPOINTED", "reason": null }
```

| 코드                    | 고정 선택 문구    |
| ----------------------- | ----------------- |
| `VERY_DISAPPOINTED`     | 매우 실망         |
| `SOMEWHAT_DISAPPOINTED` | 약간 실망         |
| `NOT_DISAPPOINTED`      | 실망하지 않음     |
| `NO_LONGER_USING`       | 더 이상 쓰지 않음 |

- 고정 문항: `이 제품을 더 이상 쓸 수 없다면 어떻겠습니까?`
- 필수 선택 응답과 선택 이유를 원자적으로 함께 저장한다. 이유는 앞뒤 공백을 정리한 1~500자 또는 null. 선택 이유만 수정하는 PATCH는 사용하지 않는다.
- 성공: `201 Created`, 본문 `{ "id": 21 }`. 네트워크 재시도에는 기존 응답을 `200 OK`로 반환한다. 설문/응답자당 한 응답을 보장하며 재시도로 답변을 덮어쓰거나 중복 집계하지 않는다.
- 응답 시각, 모집 경로 `IN_APP`, 분석 버튼 클릭 여부·판정 근거와 집계 그룹은 서버에서 기록한다. 분석 성공 여부로 클릭 기준을 바꾸거나 이력 확인 불가를 미사용으로 단정하지 않는다.
- FE는 성공한 뒤에만 완료 안내·응답 완료 표시를 적용한다. 실패 시 두 입력을 유지하고 재시도를 허용한다. 제출 전에 닫으면 응답이 생성되지 않는다.
- 계정 전환·화면 이탈 시 요청을 중단하고 늦은 응답은 무시한다. 요청 중단은 서버에 이미 저장된 응답을 취소하지 않으므로 중복 방지는 서버에서도 필요하다.

## POST `/api/pmf-surveys/{surveyId}/snooze`

- 요청 본문 없음. 서버에서 현재 시각 기준 다음 `Asia/Seoul` 날짜 00:00:00까지 숨긴다. 24시간 간격과 다르다.
- 성공: `204 No Content`. 설문 응답을 생성하거나 완료 처리하지 않는다. 같은 날짜의 재시도는 같은 만료 시각을 적용한다.
- `닫기`/X에는 이 요청을 보내지 않는다. 현재 화면에서만 닫고, 대시보드 재진입·새로고침에서는 다시 노출할 수 있다.
- FE는 브라우저에서도 같은 기한을 보관해 다른 탭·새로고침에 적용한다. 계정별로 분리하며 다른 탭의 응답 완료·오늘 숨김도 열린 팝업에 반영한다.
- 서버 저장 실패 시 로컬 숨김만 적용됐음을 안내하고 재시도/닫기를 허용한다. 로컬과 서버 모두 실패하면 숨김 실패를 안내한다.
- 자정에 현재 화면 위로 자동 표시하지 않는다. 다음 대시보드 진입에서 다시 판단한다.

## 별도 BE 이슈 작업

제목: `[Feat-BE] PMF 설문 응답 저장 및 분석 사용 여부 구분`

- [ ] 현재 설문·첫 방문 여부·기응답·오늘 숨김 기한 조회
- [ ] 필수 응답과 선택 이유 단일 저장, 응답자별 중복 방지
- [ ] KST 자정 만료의 오늘 숨김 저장 및 계정/익명 세션 구분
- [ ] 응답 시점 기준 최근 2주 분석 버튼 클릭 이력과 공식 PMF 집계 그룹 기록
- [ ] 기존 팀원 제외, 응답 시각·모집 경로·그룹별 결과 조회 수단 구현
- [ ] 권한·중복·자정·재시도·게스트 식별과 방문 이력 테스트

## FE 검증용 미리보기

`npm run dev -- --host 127.0.0.1 --port 5178` 후 `/pmf-survey-demo.html`을 연다. 실제 서버에 응답을 전송하지 않는 별도 개발 문서이며 운영 빌드에 포함되지 않는다.

- `?firstVisit=1`: 첫 방문자의 최초 대시보드 보류를 확인한다. 소식 링크로 이동 후 포트폴리오 링크로 복귀한다.
- `?fail=answer` / `?fail=snooze`: 제출/오늘 숨김의 첫 서버 저장 실패를 재현한다.
- 닫은 뒤 표시되는 `미리보기 초기화` 버튼은 이 데모 설문 상태만 초기화한다. 정상 앱의 정책을 바꾸지 않는다.
- BE 배포 전 실제 앱에서 팝업이 보이지 않는 것은 의도된 동작이다. 로컬 저장만으로 응답 저장 성공을 표시하지 않는다.
