# 소식 화면 디자인 계약

## Overview

승인된 comp10 방향을 소식과 인물 화면에 적용한다. 흰 바탕, 네이비 제목, 얇은 구분선과 평평한 목록으로 구성한다. 이 문서는 해당 화면만 다루며 전역 디자인 시스템은 변경하지 않는다. 공통 내비게이션의 탭 이름은 소식이며 별도 인물 탭 없이 인물 화면에서도 소식 메뉴를 활성화한다. 구현 기준은 같은 디렉터리의 `issue.css`다.

## Colors

`ink`는 제목과 주요 정보, `muted`는 날짜·출처·보조 문구, `line`은 행과 영역 구분에 사용한다. 목록 바탕은 `surface`를 유지한다. 플랫폼 표시는 출처를 식별하는 용도로 쓴다.

## Typography

기존 글꼴을 상속한다. 주요 화면 제목과 소식 섹션 제목은 공통 `--page-title-*` 변수를 사용한다. 데스크톱 24px, 720px 이하 22px, 굵기 700, 줄 높이 1.4, 자간 -0.03em으로 통일한다. 목록 제목은 각각 19px, 17px다. 날짜·출처는 13px로 낮춘다. 긴 제목은 줄바꿈하고, 목록의 외부 게시물 제목은 두 줄까지 보여준다.

## Layout

- 소식 홈·전체 콘텐츠·인물·뉴스 목록은 푸터 콘텐츠와 좌우 끝선을 맞춘다. 공통 `--page-side-padding`을 사용하며 데스크톱은 `16px + clamp(32px, 8vw, 128px)`, 600px 이하에서는 36px다.
- 홈 본문의 소식 제목은 시각적으로 숨긴다. 상단은 DAYNOMY 기사와 인물 미리보기를 같은 너비의 두 열로 배치하고, 아래에 오늘 올라온 통합 피드를 둔다. 720px 이하에서는 상단을 한 열로 쌓는다. 오늘 피드는 개수 제한 없이 표시하며 전체 콘텐츠 더보기에서 과거 글도 표시한다.
- 기사 영역은 한 번에 한 기사씩 3초마다 순환한다. 사진 아래에 제목을 배치하고 이미지와 제목에서 기사로 이동하며 현재 순서만 표시한다. 재생·이전·다음 버튼과 달력은 두지 않는다. 별도 조작 없이 자동으로 순환하며 키보드 포커스가 들어오면 링크를 유지하고, 떠나면 자동으로 재개한다. 동작 줄이기 설정에서는 전환 애니메이션을 생략한다. 모바일 좌우 여백도 공통 페이지 기준을 따른다.
- 목록 행은 데스크톱 상하 24px, 모바일 20px 간격을 사용한다. 외부 콘텐츠는 선택한 행 아래에서 최대 640px로 펼친다. 모바일에서는 펼친 영역이 아이콘 열까지 포함한 행 너비를 사용한다.

## Elevation & Depth

목록은 여백과 얇은 구분선으로 영역을 나눈다. 외부 콘텐츠도 목록 안에서 펼치며 별도 모달이나 배경막을 사용하지 않는다.

## Shapes

기사 이미지는 16:9 비율과 작은 모서리 곡률을 사용한다. 검색·선택·날짜·더 보기 컨트롤도 작은 곡률과 얇은 테두리를 유지한다.

## Components

- 인물 화면은 항상 `인물의 글` 제목과 `← 소식 홈` 링크를 유지한다. 선택한 인물의 지난 글까지 포함한 전체 기록과 글 수를 표시하고, 소식 전체 목록과 같은 번호 버튼으로 12개씩 이동한다. 기존 `?view=all` 링크도 계속 동작한다. API 등록일은 원본 게시 시각과 다를 수 있다.
- `/news`는 소식 홈, `/news/today`는 뉴스 목록, `/news/contents`는 전체 콘텐츠다. `/people?person={id}`는 선택한 인물의 글을 보여준다.
- 오늘의 이슈에는 한국 시간 기준 오늘 발행한 DAYNOMY 기사만 표시한다. 오늘 기사가 없으면 빈 상태와 전체 콘텐츠 링크를 표시한다. 별도 오늘의 이슈 더 보기 링크는 두지 않는다.
- 인물 미리보기는 최대 두 개의 원형 프로필 이미지·이름·플랫폼 로고와 이름·두 줄 제목 항목이다. 등록된 `profileImageUrl`이 있으면 해당 이미지를 표시하고 없으면 기본 프로필 아이콘을 사용한다. 행 사이에 얇은 구분선을 두며 아래에는 등록일만 표시한다. 섹션 링크는 화살표 없는 `전체 보기`이며, 각 행 전체를 누르면 인물 페이지로 이동한다. 관리자가 선택한 실제 이미지 외에 임의의 인물 사진은 사용하지 않는다.
- 인물 선택은 목록 위의 `전체 · 인물 이름` 버튼 메뉴다. 선택 상태는 밑줄과 굵은 글자로 표시하며 가로로 넘길 수 있다. 이름 검색창과 드롭다운은 두지 않는다.
- 전체 콘텐츠는 출처를 합쳐 최신순으로 정렬한 뒤 페이지당 12개를 표시한다. 이전·다음과 최대 6개의 페이지 번호를 제공하고, 출처 변경 시 1페이지로 돌아간다. 전체 목록은 각 출처의 과거 기록을 읽어 클라이언트에서 합친다. `/search`의 통합 검색은 별도의 `GET /api/search/contents`를 사용해 서버에서 검색·출처 필터·페이지를 계산하며, 이 검색 API를 홈·전체 목록의 통합 페이지 API로 사용하지 않는다.
- 기사 카드는 상세 화면으로 이동한다. X·Threads·YouTube는 `aria-expanded`와 `aria-controls`를 갖춘 버튼으로 해당 행 아래에서 펼치며 한 목록에서 하나만 열 수 있다. 열 때 소셜 임베드 또는 `youtube-nocookie.com` 영상 iframe을 마운트하고 원문 링크를 제공한다. 하단 글 접기 버튼은 내용을 접고 열었던 버튼으로 포커스를 돌려준다.
- 로딩·빈 결과·오류를 구분하고 소식 홈과 인물 화면의 실패한 요청에는 재시도를 제공한다. 키보드 포커스는 2px 외곽선으로 표시한다.
- 홈 연결 데이터는 `/api/news`, `/api/people`, 페이지 단위 `GET /api/contents`다. 홈 기사 영역은 오늘 피드와 뉴스 데이터를 공유하며 `/api/news/today`를 별도 호출하지 않는다. 오늘 기사 조회는 기존 `/api/news`를 100개씩 읽어 오늘 날짜의 경계까지 확인한다.
- 오늘 피드는 DAYNOMY 기사, 인물의 X·Threads·YouTube 글, 자산에 저장된 YouTube·Threads·X 콘텐츠를 합친다. 기사는 발행일, 인물 글은 API 등록일, 종목 외부 콘텐츠는 `publishedDate`가 있으면 원문 게시일·없으면 등록일을 한국 시간으로 비교한다. 날짜가 같으면 등록 시각·ID순으로 정렬한다. 외부 콘텐츠를 합칠 때 인물 글과 같은 URL 및 외부 콘텐츠 사이의 중복 URL을 제외한다.
- 종목 자료의 `publishedDate`는 원문 게시일을 입력하지 않은 신규 자료와 V42가 보완한 기존 자료에서는 한국 시간 등록일이다. 필드 존재만으로 원문 게시일 검증을 보장하지 않는다.
- 검색 결과는 기사 발행 시각·외부 자료 등록 시각 기준의 서버 순서를 유지하며 소식 피드의 게시일 정렬과 구분한다. 로컬 개발 서버의 샘플 기사는 화면 검토용으로만 표시하고 배포 빌드와 테스트에서는 포함하지 않는다.

## Do's and Don'ts

- Do: 인물 미리보기에서는 이름과 실제 글로 인물을 식별한다.
- Do: 서버에 등록된 게시물과 날짜를 기준으로 목록을 구성한다. 인물 미리보기는 각 인물의 최근 등록 글을 기준으로 고른다.
- Don't: 임의의 인물 사진, 인기 순위·조회수·반응 수를 만들지 않는다.
- Don't: 저장된 외부 콘텐츠를 플랫폼 전체의 실시간 수집 결과로 설명하지 않는다.

출처 필터는 전체·DAYNOMY Issue·X·Threads·YouTube 알약형 버튼으로 표시한다. 선택된 버튼은 남색 바탕과 흰 글자, 나머지는 연한 회색 바탕을 사용하며 `aria-pressed`로 선택 상태를 제공한다. 좁은 화면에서는 가로로 스크롤한다.
